## ตัวเลขที่แก้บ่อย
- หุ้นรายเดือน: shares.accounts[].monthly (บาท)
- หุ้นยกมา: opening_amount (บาท) และ opening_units (จำนวนหุ้น) ต้องสอดคล้องกัน
- ยอดหุ้นสะสม = ยอดยกมา + รายการที่ received ไม่ใช่ null
- อัตราปันผล: returns.allocations[].dividend_rate เช่น 400 = 4.00%
- อัตราเฉลี่ยคืน: rebate_rate เช่น 500 = 5.00%
- เงินที่ชื่อ field ลงท้าย Cents หรือ cents เป็นสตางค์ เช่น 100000 = 1,000 บาท
- หุ้น amount และยอดกู้ amount เป็นบาท ตามรูปแบบเดิม
- สินเชื่อ annualRate เป็นเปอร์เซ็นต์ เช่น 5.5 = 5.5% ต่อปี

ห้ามแก้เฉพาะยอดเงินฝากโดยไม่แก้ประวัติรายการให้สอดคล้องกัน เพราะดอกเบี้ยคำนวณจากรายการที่ยืนยันแล้ว

## อ่านและบันทึก
store.ts: readDatabase() อ่านไฟล์ล่าสุด / updateDatabase(callback) บันทึกเมื่อ callback สำเร็จเท่านั้น ถ้า throw ไม่บันทึก
shares.ts: แปลงหมวดข้อมูลให้ฟังก์ชันหุ้นเดิมอ่านได้ โดยไม่สร้างข้อมูลซ้ำ
ทุกการเขียนใช้ lock และ atomic rename ป้องกันการเขียนทับกัน มีการตรวจว่าผู้ใช้แก้ไฟล์ใน VS Code ระหว่างบันทึกหรือไม่

ภายใน object ใช้รูปแบบ JSON (คีย์และข้อความใส่เครื่องหมายคำพูดคู่ ไม่มี comment หรือ trailing comma) ไฟล์ใช้ .ts เพื่อเปิดอ่านใน VS Code ได้ แต่ระบบ parse เป็นข้อมูลเท่านั้น ไม่รันโค้ดในไฟล์

สินเชื่อไม่มีการเลือกหรืออัปโหลดไฟล์ และไม่บังคับเอกสารก่อนส่งตรวจหรืออนุมัติ loans.documents คงไว้รองรับข้อมูลรุ่นเดิม แต่ไม่มี API อ่านหรืออัปโหลดใช้งาน

ระบบใหม่ไม่ต้องใช้ .sqlite, SQL หรือ Prisma สำเนาเดิมอยู่ archive/ เท่านั้น เงินฝากและสินเชื่อเดิมไม่ได้ถูกนำเข้าจาก PostgreSQL โดยอัตโนมัติ

## บัญชีเงินฝากหลายรูปแบบ
สมาชิกเปิดได้ประเภทละหนึ่งบัญชี: savings (SA-), special (SP-), monthly (MO-) ทุกบัญชีอ้าง member เดียวกันแต่แยกยอดและประวัติ
รายการฝาก/ถอนใหม่ใช้ requestId ที่ฟอร์มสร้างภายใน ป้องกันกดส่งซ้ำโดยไม่ต้องกรอกเลขอ้างอิง รายการเก่ายังคงข้อมูลเดิมไว้แต่ไม่แสดงเลขอ้างอิงในหน้าจอหรือใบแจ้งยอด

## การใช้งานบน Vercel แบบข้อมูลถาวร

- ในเครื่องยังอ่าน/เขียน `database/data.ts` ตามเดิม
- Vercel ตั้ง `COOP_DATABASE_STORAGE=vercel-blob` และเชื่อม private Blob store ผ่าน `BLOB_READ_WRITE_TOKEN`
- ออนไลน์เก็บรูปแบบข้อมูลเดียวกันไว้ในไฟล์ private `coop-finance/data.ts` ไม่ได้เก็บใน `/tmp`
- API โหลด snapshot แยกแต่ละคำขอด้วย `database/remote.ts` จากนั้น service ตรวจสิทธิ์และข้อมูลตามเดิม
- บันทึกด้วย ETag (`ifMatch`) หากมีคนอื่นบันทึกก่อน จะตอบ 409 ให้ลองใหม่ แทนการเขียนทับข้อมูล
- ระบบรอบันทึกสำเร็จก่อนตอบว่าบันทึกแล้ว จึงไม่สูญหายเมื่อ Vercel เปลี่ยน instance หรือ deploy ใหม่
- การแก้ไฟล์ใน VS Code มีผลเฉพาะเครื่อง ไม่เขียนทับข้อมูลออนไลน์เมื่อ deploy; การอัปโหลดข้อมูลตั้งต้นทำเพียงครั้งเดียว
- ห้ามใส่ token ในโค้ด, client component, public/ หรือ Git

## GitHub และข้อมูลในเครื่อง

`data.ts` เป็นไฟล์ข้อมูลที่ใช้งานจริง จึงถูกละเว้นจาก Git ใช้ `data.example.ts` ที่มีข้อมูลสมมุติสำหรับเครื่องใหม่ รัน `npm install` หรือ `npm run setup` เพื่อสร้างไฟล์เฉพาะเมื่อยังไม่มี การอัปโหลดโค้ดไม่คัดลอกหรือรีเซ็ตข้อมูลออนไลน์
